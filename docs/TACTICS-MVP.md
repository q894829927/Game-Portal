# 第二款游戏：原创奇幻战棋 MVP 构想

> 暂定项目名：未命名战棋（Tactics Game）。这是新游戏的项目提案，不属于静态门户功能，也不是已经实现的游戏。

## 设计目标

参考经典回合制战棋的**可玩性结构**：方格地图、单位行动、地形策略、战斗预览、角色成长；不复制任何既有游戏的角色、职业名称、地图、美术、剧情或品牌素材。

## 第一版只做一个可通关关卡

- 地图：10×8 正方格，起始点、山丘、树林、平地和道路。
- 阵容：4 名友军（剑士、枪卫、弓手、术士作为原创原型名），6 名敌人。
- 回合：玩家回合→敌方回合；每单位每回合移动一次、执行一次主要动作；行动完毕变灰。
- 移动：网格寻路，地形移动消耗，障碍阻挡；高亮合法移动范围与攻击范围。
- 战斗：攻击/反击、伤害和命中率预览、武器射程与地形防御；第一版用可解释的计算公式，不使用隐藏随机器制。
- AI：优先攻击可击败的目标，其次攻击最近可打击目标；无目标时向目标区推进。
- 胜败：击败关底敌方指挥官获胜；全部友军倒下失败。
- 成长：经验值、升级、简单职业初始属性和技能差异；第一版不用转职系统。
- 数据：地图、角色、物品、敌人、关卡由 JSON/TS 数据表配置；回合逻辑与客户端表现分离，方便回放、自动测试和未来联机。

## 推荐独立技术架构

- 独立 GitHub 仓库：`Tactics-Game`。
- 客户端：TypeScript + Phaser（沿用已有网页游戏开发经验），不和 `Rift-Resonance` 共享游戏战斗源码。
- V0 单机纯前端，使用固定 RNG seed 保证可重复测试。不要过早添加 Colyseus 服务器；先证明一关好玩。
- 后续如果确有多人对战需求，再抽出服务端权威的回合状态机。

## 分阶段执行

1. **T0**：规则文档、地图/角色配置、基础回合状态机单元测试。
2. **T1**：方格地图显示、点击选择单位、移动范围、A* 寻路。
3. **T2**：攻击/反击、伤害预览、行动结束、简单敌方 AI。
4. **T3**：唯一关卡开局、目标提示、胜败结算、重新开始。
5. **T4**：角色属性与经验成长、动作/音效、存档和浏览器适配。

## 完成标准

用户能在浏览器中从开局部署，操作四名单位，在规则可预览的情况下战胜六名敌人，并看到明确的结算结果；桌面网页无阻塞性错误，重要计算有自动化测试。

## 未来的原创特色（先讨论，暂不实施）

- **战场共鸣**：不同职业相邻行动会创造一次性战术效果（弓手助攻、术士改变地形等），避免仅复制传统武器克制。
- **抉择事件**：章节中通过地图目标、支援单位和地图机关创造重玩价值。
- **轻量随机化**：在保持策略透明的前提下对支线地图/敌军阵容做可控变化，不让一次随机未命中决定整局胜负。
